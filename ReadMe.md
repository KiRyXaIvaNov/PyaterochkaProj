# Виртуальная техническая поддержка Томского политехнического университета

## 1. Описание проекта

Проект представляет собой веб-систему виртуальной технической поддержки ТПУ. Пользователь может получить пошаговое решение типовых проблем из базы знаний, задать нестандартный вопрос нейросети или передать обращение специалисту.

Система построена по гибридной архитектуре:

- **C++ классификатор** — первая ступень обработки запроса. Он выполняет токенизацию, фильтрацию служебных слов и классификацию по ключевым словам с учетом опечаток.
- **SQLite + база знаний** — хранение пользователей, сообщений, обращений и готовых инструкций.
- **ChromaDB** — семантический поиск по базе знаний для запросов, которые не удалось определить с помощью C++ классификатора.
- **Qwen 2.5:7b через Ollama** — локальная языковая модель для обработки нестандартных запросов и формирования ответа на основе найденного контекста.

## 2. Основной сценарий работы

1. **Авторизация.** Пользователь вводит адрес электронной почты. Для администратора используется учетная запись `admin@tpu.ru`; остальные пользователи попадают в интерфейс чата.
2. **Классификация.** Сообщение пользователя передается в скомпилированный C++ модуль.
3. **Поиск решения:**
   - если C++ определил категорию, Python-сервер ищет подходящую статью в базе знаний и при наличии совпадения возвращает готовые пошаговые инструкции без вызова Qwen;
   - если категорию определить не удалось, выполняется семантический поиск в ChromaDB;
   - если подходящий контекст найден, он передается локальной модели Qwen для формирования ответа;
   - если релевантный контекст не найден, Qwen обрабатывает запрос как нестандартный и просит пользователя уточнить необходимые детали.
4. **Передача специалисту.** Пользователь может явно выбрать действие «Нужен специалист». Только после этого создается обращение в SQLite и оно появляется в панели администратора.
5. **Работа специалиста.** Администратор видит обращения, может ответить пользователю и закрыть обращение.
6. **История чата.** Сообщения пользователя и ответы системы сохраняются и доступны в истории диалога.

Обычное сообщение пользователя само по себе не создает обращение к специалисту.

## 3. Используемые технологии

- **Frontend:** React, Vite, React Router, Tailwind CSS.
- **Backend:** Python 3.11, FastAPI, Uvicorn, Pydantic.
- **Алгоритмическое ядро:** C++17, pybind11, nlohmann/json.
- **Базы данных:** SQLite и ChromaDB.
- **ИИ-модуль:** Qwen 2.5:7b, запускаемый локально через Ollama.
- **Контейнеризация:** Docker и Docker Compose.

## 5. Запуск проекта через Docker

Для проверки проекта рекомендуется использовать Docker Compose.

### Требования

Необходимо установить **Docker Desktop** с поддержкой Docker Compose.

### Запуск

Откройте терминал в корневой папке проекта и выполните:

```bash
docker compose up --build
```

Во время первого запуска Docker:

1. собирает backend;
2. устанавливает Python-зависимости;
3. компилирует C++/pybind11 классификатор;
4. запускает Ollama;
5. скачивает модель `qwen2.5:7b`;
6. собирает frontend;
7. запускает все необходимые контейнеры.

После запуска веб-интерфейс доступен по адресу:

```text
http://localhost:5173
```

Backend API доступен на:

```text
http://localhost:8000
```

### Важно для первого запуска

Образ Ollama и модель Qwen могут занимать несколько гигабайт, поэтому первый запуск требует свободного места на диске и доступа к интернету для загрузки Docker-образов и модели.

Модель сохраняется в Docker volume `ollama_data`, поэтому при следующих запусках повторно скачивать ее не требуется.

Если требуется остановить проект:

```bash
docker compose down
```

Чтобы полностью удалить контейнеры и сохраненную модель Ollama:

```bash
docker compose down -v
```

## 6. Ограничения MVP

- Авторизация является упрощенной и не подключена к реальной системе учетных записей ТПУ.
- C++ классификатор работает по заданным категориям и ключевым словам и не заменяет полноценный морфологический анализ русского языка.
- Qwen запускается локально через Ollama, поэтому скорость генерации зависит от ресурсов компьютера проверяющего.
- При первом запуске для загрузки Docker-образов и модели требуется интернет-соединение.
- Проект не использует внешние коммерческие API для работы чат-бота.

## 7. Проверка основных функций

После запуска рекомендуется проверить следующие сценарии:

1. Войти обычным пользователем.
2. Отправить типовой запрос, например `Не работает Wi-Fi`, и проверить получение инструкции из базы знаний.
3. Отправить нестандартный запрос и проверить обработку через Qwen.
4. Нажать **«Нужен специалист»** и убедиться, что обращение появилось в панели администратора.
5. Войти под `admin@tpu.ru`, открыть обращение и отправить ответ пользователю.
6. Проверить историю сообщений в чате.
