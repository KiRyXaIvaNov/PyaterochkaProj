# Виртуальная техническая поддержка Томского политехнического университета

## 1. Описание решения

Проект представляет собой интеллектуального виртуального помощника для студентов и сотрудников ТПУ, автоматизирующего обработку обращений по 11 ключевым категориям (ИТ-сервисы, учебный процесс, кампус, общежития). 

В основе системы лежит **гибридная двухступенчатая архитектура**, сочетающая детерминированные алгоритмы и семантический поиск, что исключает риск "галлюцинаций" ИИ и минимизирует нагрузку на сервер:

* **Первая линия (C++ Модуль):** Сверхбыстрое ядро, выполняющее токенизацию, фильтрацию стоп-слов, регулярные выражения и расчет расстояния Левенштейна для отлова опечаток в ТПУ-сленге.
* **Вторая линия (ChromaDB + RAG):** Векторная база данных, которая подключается при обработке сложных, абстрактных запросов для извлечения точного контекста.
* **Интерфейс ответов (Qwen 2.5:7b):** Локальная большая языковая модель, которая используется строго как инструмент генерации вежливых, человечных ответов на основе верифицированного контекста из базы знаний.

---

## 2. Описание основного сценария

1. **Авторизация:** Пользователь вводит почту и пароль. При вводе `admin@tpu.ru` система открывает интерфейс оператора. При вводе любой другой почты — интерфейс чат-бота.
2. **Анализ запроса:** Текст сообщения пользователя передается в скомпилированный C++ модуль (алгоритм токенизации, стоп-слов и расстояния Левенштейна).
3. **Ветвление логики (в порядке приоритета):**
   * **Шаг 1 — Категория определена:** C++ распознает категорию (например, `Wi-Fi` или `VPN`). Python-сервер ищет внутри категории конкретную проблему по ключевым словам и отвечает пошаговой инструкцией прямо из JSON-базы знаний (`bz.json`) — без обращения к нейросети. Если внутри категории конкретную проблему определить не удалось, бот задает уточняющий вопрос из каталога услуг для этой категории.
   * **Шаг 2 — Категория не определена, но найден похожий прецедент:** Если C++ возвращает `unknown`, подключается векторная база ChromaDB. Если находится семантически близкий прецедент, локальная модель Qwen 2.5:7b формулирует ответ на основе найденного контекста.
   * **Шаг 3 — Ничего не найдено:** Если и векторный поиск не дал релевантных результатов, отвечает Qwen 2.5:7b — вежливо уточняет детали проблемы, не выдумывая решение.
4. **Эскалация специалисту:** На любом шаге пользователь может нажать «Нужен специалист». Только в этот момент в БД SQLite создается «Карточка обращения», и диалог появляется в панели оператора. До этого момента карточек в админ-панели нет — бот обрабатывает обращения самостоятельно.
5. **Панель оператора:** Карточки обращений, переданных специалисту (категория, уверенность C++ ядра, текст проблемы), отображаются на экране администратора, который отвечает пользователю прямо оттуда.

## 3. Используемые технологии

* **Frontend:** React, Axios (веб-интерфейс чата и админ-панели).
* **Backend:** Python 3.12, FastAPI, Uvicorn, Pydantic (веб-шлюз и оркестратор логики).
* **Алгоритмическое ядро:** C++ (ISO C++17), pybind11, nlohmann/json (модуль предобработки, стемминга и исправления опечаток Левенштейна).
* **Базы данных и Хранилища:** SQLite (история сообщений, карточки тикетов, сессии), ChromaDB (векторное хранилище эмбеддингов базы знаний).
* **ИИ-модуль:** Локальная языковая модель Qwen 2.5:7b.

---

## 4. Дополнительный функционал

* **Метрика "Уверенность системы":** Математический расчет процента уверенности детерминированного классификатора C++ на основе весов точных совпадений и исправленных опечатками токенов (выводится в карточку админа).
* **Полная автономность:** Решение (включая С++ алгоритмы, СУБД и нейросеть Llama) разворачивается локально, не требует интернет-соединения и внешних коммерческих API, гарантируя 100% безопасность персональных данных сотрудников и студентов ТПУ.
* **Мониторинг удовлетворенности (CSAT):** Система включает модуль оценки качества ответов. Пользователь может оценить диалог через UI-кнопки, либо Qwen 2.5 автоматически определяет тональность финального сообщения (Sentiment Analysis). Данные записываются в карточку тикета, позволяя оператору в админ-панели фильтровать проблемные зоны и отслеживать общую статистику удовлетворенности студентов ТПУ.

---

## 5. Ограничения MVP

* Эмуляция единой системы аутентификации ТПУ (вход по маске почты без реальной валидации паролей в Active Directory).
* Базовая фильтрация стоп-слов в C++ оптимизирована под русскоязычные и англоязычные ИТ-запросы, но не включает глубокий морфологический анализ редких частей речи.
* Контекстное окно локальной модели Qwen 2.5:7b ограничено ресурсами CPU/GPU хост-машины, в связи с чем история переписки в рамках одной сессии MVP сохраняет до 20 последних реплик диалога.
